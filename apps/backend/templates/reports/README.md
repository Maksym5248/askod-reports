# Шаблони звітів

- `originals/` — незмінені файли користувача. Це еталон оформлення,
  а не джерело показників для бази даних.
- `sources.json` — назви, фактичні формати й SHA-256 оригіналів.
- `styled-appendices.json` — чотири підготовлені XLS у base64,
  у порядку додатків 1–4. Прикладові показники очищені, стилі збережені.
- `styled-word.json` — підготовлені DOCX у base64 для журналу та ЗПІ.
  Ключі: `journal`, `public-information`.

JSON вбудовується в збірки desktop/backend: запущеному застосунку не потрібні
Downloads або зовнішня програма Office. Код заповнення розташований у
`src/infrastructure/reports/template-report-writer.ts` та `styled-xls.ts`.

## Заміна шаблонів

1. Додати новий оригінал у `originals/` та оновити контрольну суму.
2. Перевірити фактичний формат. Наявні Word-файли з розширенням `.docx` — старі DOC,
   побайтово ідентичні попереднім версіям. Для уникнення конвертації потрібен
   файл, збережений у Microsoft Word через «Зберегти як → Документ Word (.docx)».
3. Підготувати копію: очистити прикладові числа, зберегти всі властивості
   оформлення, встановити місця підстановки організації та періоду.
4. Для журналу зберегти два заголовкові рядки та один рядок-зразок з
   `{{cell0}}`…`{{cell10}}`; текстові параметри — `{{organization}}`, `{{period}}`.
5. Оновити відповідний base64-ресурс. Саме копіювання нового оригіналу
   не змінює робочий шаблон автоматично.
6. Запустити тести `apps/backend/tests/integration/reports.test.ts`,
   перевірити експорт у Electron і порівняти оформлення з оригіналом.

BIFF8-адаптер прив’язаний до структури чотирьох наданих додатків. Якщо
змінюються координати клітинок або структура аркушів, адаптер теж потрібно
оновити. Не використовувати його як редактор довільних XLS.
