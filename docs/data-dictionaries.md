# Довідники даних журналу

## Джерело та межі

Проаналізовано `journal_15_09_2026_12_49_13.xlsx`: 300 рядків документів.
Користувач затвердив спостережені значення як початкові закриті переліки.
Це не повний офіційний довідник АСКОД. Нові значення потребують явного оновлення коду.

Джерело правил: [document-enums.ts](../apps/backend/src/domain/documents/document-enums.ts).
Використано `as const` переліки та похідні TypeScript union types — domain enum-и,
незалежні від Prisma. У SQLite зберігається точний текст у наявних String-колонках.
SQL enum/CHECK-обмеження не додаються; перевірка виконується перед збереженням у domain,
а mapper перевіряє значення при читанні БД. Прямий запис SQL обходить правила застосунку.

## Унікальність документа

У файлі немає повторів «номер + рік реєстрації». Це підтверджує сумісність файла
з прийнятим правилом, але не доводить унікальність номерів у всіх журналах АСКОД.
Поточний ключ залишається `(registrationNumber, registrationYear)`.
У межах одного імпорту повтор ключа — помилка; між імпортами — оновлення з історією.

У цьому файлі немає конфліктів код–назва або частково заповнених пар.
Значення ще не звірялися з офіційним класифікатором; не слід називати ці коди
КАТОТТГ чи виводити офіційний код із двох цифр.

Рекомендована майбутня модель — довідник `Territory` з технічним ID, системою
кодів/джерелом, строковим externalCode, назвою, типом території та optional parentId.
Документ посилається на territoryId; raw/snapshot зберігають початкові код і назву.
Унікальність externalCode потрібно визначати в межах системи кодів.
Це дозволить включити області, міста та райони без переліку enum у коді.
Невідому або суперечливу пару слід відхиляти після затвердження повного довідника.

Наразі міграцію територій не виконано: зберігаються наявні `territoryCode` і `territory`.
Для впровадження потрібне підтвердження системи кодів та її повний довідник.

## Excel-звіт про помилки

При ImportValidationError API повертає 422: `error`, перші 100 `issues`, повний
`issueCount`, `report: { fileName, base64 }`. XLSX генерує ExcelJS adapter через
application interface `ImportErrorReportWriter` та use case `GenerateImportErrorReport`.
Файл не записується на серверний диск; renderer пропонує завантаження через Blob.

Аркуш «Помилки імпорту»: рядок вихідного Excel, поле, отримане значення,
пояснення виправлення та дозволені значення. Усі знайдені помилки нормалізації
включено, без ліміту 100. Структурні помилки XLSX можуть зупинити перевірку раніше.
«Інструкція» пояснює наступні дії. Значення записуються як текст, а не Excel-формули.
Технічні HTTP-помилки 400/401/413/415/500 не створюють звіту даних.
При невдалому імпорті жодні документи або записи історії не зберігаються.

## Оновлення enum

1. Погодити точне значення з власником даних.
2. Оновити `documentEnums`, тести та цей документ.
3. Перевірити сумісність наявних даних перед видаленням чи перейменуванням значення.
4. Зібрати й поставити нову версію застосунку.
