# Таблиця та керування документами

## Відображення

Таблиця показує 43 колонки у початковому порядку експорту АСКОД, а також
«Створено в застосунку», «Оновлено в застосунку» та дію перегляду історії.
`№ з/п` обчислюється для поточного відсортованого списку. Початковий номер
із кожного Excel зберігається в ImportRow.raw.

Назви, порядок, типи редакторів та дозволені enum-значення надходять із
`GET /api/documents/columns`. Backend формує їх із journalColumns і domain enum-ів.
Renderer отримує лише HTTP-контракти й не імпортує Excel adapter або domain.

TanStack Table керує видимістю, розміром, порядком і вибором рядків.
Mantine надає редактори, модальні вікна та UI. Усі колонки спочатку видимі.
Номер рядка, номер документа й дата реєстрації закріплені ліворуч, заголовки — зверху.
У меню «Колонки» можна приховувати інші поля та змінювати їх порядок кнопками.
Ширина змінюється перетягуванням правого краю заголовка; подвійний клік скидає ширину.
«Відновити вигляд як у файлі» скидає порядок, видимість і розміри.
Налаштування живуть у Zustand/localStorage; дані документів — у TanStack Query.

Пошук за номером, змістом або заявником, фільтр виду документа, сортування й
пагінація виконуються на сервері. Їх параметри зберігаються в URL.
Сторінка містить до 25 рядків; вибір обмежений поточною сторінкою та скидається
при зміні пошуку, фільтрів, сортування або сторінки.

## Службові поля

- `createdAt`: перше збереження документа в застосунку.
- `updatedAt`: остання зміна даних або м’яке видалення.
- `version`: ціла версія для захисту від конкурентного редагування.
- `deletedAt`: час приховування; null для активних документів.

Міграція відновлює createdAt із найранішого успішного імпорту, updatedAt —
з останнього результату created/updated. Unchanged не оновлює дату. Для записів
без історії використовується час міграції, бо справжня дата невідома.
Новий імпорт без змін і збереження того самого значення не змінюють updatedAt/version.

## Редагування

Клік клітинки відкриває редактор. Enum — Select, дата — date input, кількість —
числове поле, текст — багаторядкове поле. Кнопка «Зберегти» підтверджує зміну,
«Скасувати» або Escape скасовують її. Enter зберігає дату/число/enum;
у багаторядковому тексті Enter додає новий рядок. Blur не зберігає автоматично.
Службові дати й номер рядка не редагуються.

`PATCH /api/documents/:id` приймає `{ version, field, value }`.
ManageDocuments перевіряє поле, завантажує актуальний документ, повторно запускає
нормалізацію та enum-валідацію, передає збереження репозиторію.
Репозиторій атомарно перевіряє версію, оновлює документ і додає DocumentChange.
Номер/рік залишаються унікальними; UUID не змінюється при ручній зміні ключа.
Конфлікт або неправильне значення — 409, відсутній/видалений документ — 404,
неправильна форма HTTP-запиту — 400. Помилка показується в клітинці.

Новий імпорт може перезаписати ручні виправлення відповідно до попереднього
правила «останній успішний імпорт». При зміні ключа документа наступний імпорт
зі старим ключем створить інший документ. Інтерфейс попереджає про вплив імпорту.

## Групове видалення

`POST /api/documents/delete` приймає `{ items: [{ id, version }] }`, від 1 до 100
різних документів. Користувач підтверджує вибір у діалозі.
В одній транзакції встановлюються deletedAt/updatedAt, збільшується version та
створюється історія. Якщо хоча б один документ змінено або вже видалено, вся
операція відкочується з 409. Видалені документи виключені зі списку й лічильника.

ImportRow, початкові значення й DocumentChange залишаються. Ключ документа
залишається зайнятим. Повторний імпорт видаленого ключа відхиляє весь файл із
поясненням і Excel-звітом; автоматичного відновлення немає. Кошик, відновлення
та остаточне очищення даних ще не реалізовані.

## Історія

`GET /api/documents/:id/history` повертає імпортовані знімки та ручні зміни.
Для manual зберігаються before/after, для delete — попередні дані й deletedAt.
Події імпорту походять із наявних ImportRow та показують знімок на момент імпорту.
Кнопка «Історія» відкриває панель із часом, джерелом і значеннями полів.
Ідентифікації автора немає, доки не впроваджено автентифікацію.

## Перевірки

Інтеграційні тести покривають конфлікти ключів/версій, enum-помилки, no-op,
історію, атомарність видалення, заборону відновлення імпортом та перенесення дат
зі старої БД. Окремі [E2E-сценарії](e2e-testing.md) перевіряють редагування клітинки,
порядок/видимість колонок, reload і видалення. Кожен тест має ізольовану БД.
