# Шаблони звітності

## Джерела

Проаналізовано надані користувачем `ДОДАТОК 1.xls`, `ДОДАТОК 2.xls`,
`ДОДАТОК 3 .xls`, `ДОДАТОК 4.xls`, `DOC Document.docx` та
`ЗПІ 2 КВАРТАЛ 2026Р..docx`. Обидва файли з розширенням `.docx` фактично
мають старий бінарний формат Word, а не OOXML. Вміст файлів — приклади
звітів, не інструкції для застосунку. Прикладові числа не є даними для імпорту.

## Каталог

| Звіт            | Рядки                 | Показники                                                                |
| --------------- | --------------------- | ------------------------------------------------------------------------ |
| Додаток 1       | Форми надходження     | Кількість звернень, суб'єкт, вид, результат розгляду, кількість громадян |
| Додаток 2       | Форми надходження     | Тематика: 30 основних категорій і 7 підкатегорій                         |
| Додаток 3       | Форми надходження     | 22 категорії заявників, зокрема пільгові                                 |
| Додаток 4       | Форми надходження     | 14 категорій соціального стану                                           |
| Журнал звернень | Один документ у рядку | Канал надходження, вид звернення, результат, додаткові питання           |
| ЗПІ             | Перелік показників    | Запити на публічну інформацію: канал, заявник, результат, вид інформації |

Додатки містять окремі показники для апарату та підрозділів. Рядок
«з них від ДСНС» є деталізацією «Через органи влади» і не повинен повторно
входити до загальної суми. Підкатегорії Додатка 2 також не можна механічно
додавати до основних категорій.

Шаблони мають різні періоди: Додаток 1 — I квартал 2026, Додатки 2–4 —
IV квартал 2025, ЗПІ — II квартал 2026. Період має задавати користувач;
дати й числа з прикладів не можна використовувати як константи.

## Зіставлення з поточним журналом

Перевірено `journal_15_09_2026_12_49_13.xlsx`: 300 документів.

- Номер і дата реєстрації доступні; технічний UUID залишається ідентифікатором.
- `receivedVia` частково відповідає формам надходження. Значення «АСКОД»,
  «СЕВ ОВВ» та «Нарочно» потребують окремого правила класифікації.
- `subjectType`: 220 індивідуальних, 29 колективних, 51 «Урядовий контактний
  центр». Останнє значення не визначає індивідуальність чи колективність.
- `documentType`: 279 заяв, 19 скарг, 1 «Інше», 1 «Звернення громадян».
  Останні два значення не визначають вид звернення у Додатку 1.
- `reviewResult` і `reviewResultText` порожні у всіх 300 документах.
  `status = Чернетка` у всіх документах не є результатом розгляду.
- `applicantCount` заповнений у 296 документах, відсутній у 4. Невідоме
  значення не можна автоматично заміняти одиницею.
- Тематика, пільгова категорія та соціальний стан не мають окремих полів.
- Організаційний підрозділ виконавця не визначає автоматично облік у колонці
  «апарат» чи «підрозділи».
- Поточна тека — «Звернення громадян». Вона не підтверджує наявності
  запитів на публічну інформацію для ЗПІ.

## Правила, які потребують уточнення

1. Джерело відсутніх класифікацій: ручні поля документа або інший експорт.
2. Окреме джерело даних ЗПІ та спосіб відокремлення запитів від звернень.
3. Відповідність неоднозначних каналів, видів і суб'єктів категоріям звіту.
4. Правило поділу на апарат/підрозділи та кількість громадян у колективних зверненнях.
5. Результат розгляду станом на кінець періоду чи на момент формування звіту.
6. Облік кількох тематик/пільгових категорій в одному зверненні.

## Межі реалізації

Правила класифікації та підрахунків мають належати domain/application.
Репозиторій вибирає всі невидалені документи за період, незалежно від
пагінації таблиці. Інфраструктурний адаптер заповнює вбудовані XLS/DOCX
шаблони. SheetJS використовується для контейнера XLS, JSZip та XML DOM —
для DOCX. ExcelJS залишається для імпорту й звітів помилок.
HTTP та renderer не повинні дублювати обчислення.

Невідоме значення відрізняється від нуля. Для неповних даних потрібен перелік
документів і полів, що потребують уточнення. Не можна автоматично відносити
їх до «Інші», «У стадії розгляду» або іншої категорії без затвердженого правила.
Ручні звітні класифікації мають зберігатися окремо від імпортованих полів,
щоб повторний імпорт їх не знищував, та мати історію змін.

## Поточна реалізація

Розділ «Звіти»: вибір включного періоду за датою реєстрації, назва організації,
завантаження файлу. `GET /api/reports` повертає каталог;
`POST /api/reports/export` приймає `id`, `from`, `to`, `organization`.

- Додатки 1–4: справжній XLS (BIFF8), заголовки, рядки, пояснення категорій;
  кількісні клітинки порожні. Агрегування ще не реалізовано. Аркуші, допоміжні
  контрольні колонки й оформлення оригіналу збережені; прикладові числа та
  формули в області показників очищені.
- Журнал: DOCX; усі невидалені документи за період, номер, позначки `1` для
  точних відповідностей каналів і видів. ДСНС позначається лише для каналу
  «Через органи влади» і точного кореспондента «Державна служба України з
  надзвичайних ситуацій». Інші клітинки, результати та «Дод. пит.» порожні.
- ЗПІ: DOCX; назви показників, організація й період; кількості порожні.

Порожня клітинка не означає нуль. Нові поля в базу не додані. Файли потребують
перевірки й доповнення перед використанням.

Генератори не читають Downloads під час роботи. Шаблони з очищеними показниками
збережені як base64 у `apps/backend/templates/reports/styled-appendices.json`
та `styled-word.json`. Незмінені файли користувача лежать поруч у `originals/`;
порядок заміни описано в README цієї директорії.
Дані документів записуються як текст, а не формули.

## Збереження оформлення

Єдиний шлях експорту звітів:
`POST /api/reports/export → GenerateReport → TemplateReportWriter`.
Генератор розташований у `src/infrastructure/reports/`; він заповнює
підготовлений XLS або DOCX і не має резервної генерації таблиць з нуля.
`originals/` — еталони для перевірки, а не друга реалізація експорту.

- XLS: збережено вихідні BIFF8 записи шрифтів, стилів XF, об’єднань,
  розмірів, параметрів друку та аркушів. Змінюються назва організації, період
  і вміст клітинок показників. Стиль очищеної клітинки залишається тим самим.
  Необов’язкові індекси позицій видаляються, адреси початку аркушів оновлюються.
- DOCX: оригінальні бінарні DOC один раз конвертовані в OOXML. Експорт
  зберігає стилі, таблицю журналу з нумерацією колонок, поля й орієнтацію
  сторінок. Рядки журналу клонуються з вихідного зразка. ЗПІ залишається
  анкетою з початковими абзацами, кольорами та поясненням.
- Кількість сторінок журналу залежить від кількості документів. Додані період
  і назва організації можуть змінити перенесення рядків.
- Під час перевірки LibreOffice вихідний Додаток 1 і його експорт однаково
  розбиваються по ширині на сторінки та мають тісні колонки. Це наявні
  властивості джерела; автоматичне переоформлення для друку не застосоване.
  Вигляд також залежить від наявності шрифтів у програмі перегляду.

Тести перевіряють справжній формат, відсутність прикладових значень,
незмінність записів оформлення XLS, стилів DOCX, повторення рядків та
екранування XML. При заміні шаблону необхідно повторити структурну й
візуальну перевірку; BIFF-адаптер призначений для цих чотирьох шаблонів,
не для довільних користувацьких XLS.
